iOS App Store Publishing Guide

Complete end-to-end submission flow for Flutter iOS apps. Based on real submission of MaiCafe (May 17, 2026).

Overview

Publishing a Flutter app to the iOS App Store takes ~2–3 hours end-to-end if all prerequisites are ready. The flow has 16 main steps across 4 phases:

  1. Apple Developer setup — register app, configure push, create signing identity
  2. Firebase setup — wire APNs key for iOS push notifications
  3. Xcode build & upload — sign, archive, distribute
  4. App Store Connect — metadata, screenshots, privacy, submit
📌 Two Paths Inside This guide has two paths depending on whether you have a physical iPhone for testing. Both end at the same place. See Decision Tree.

Prerequisites

Required before you start

  • Mac computer running macOS 14+ (Sonoma or later)
  • Xcode 15+ installed (free from Mac App Store, ~15GB)
  • Flutter SDK 3.35+ installed and on PATH
  • CocoaPods installed (sudo gem install cocoapods)
  • Apple ID with access to the client's developer team
  • Client must have:
    • Active Apple Developer Program membership ($99/year)
    • Accepted the latest Program License Agreement (PLA)
    • Added you as Admin or App Manager in App Store Connect & Developer team

Flutter project requirements

  • pubspec.yaml has version set (e.g., version: 1.0.0+1)
  • ios/Runner/Info.plist has CFBundleDisplayName
  • App icon present at ios/Runner/Assets.xcassets/AppIcon.appiconset/Icon-App-1024x1024@1x.png (no transparency, no rounded corners)
  • Bundle identifier set in Xcode (typically com.yourdomain.appname)
  • If using Firebase: ios/Runner/GoogleService-Info.plist present and configured

Decision Tree: iPhone or No iPhone?

Do you have a physical iPhone available for testing?

✅ YES — I have an iPhone

Use Automatic Signing. Xcode handles certificate + profile creation automatically. Connect your iPhone via USB and Xcode will register it to the team.

Pros: Less manual configuration. Can test on device before uploading.

→ Follow Path A at step 5.

❌ NO — No iPhone available

Use Manual Signing with a Distribution profile. Skips the development profile requirement (which needs a registered device).

Pros: Works without any iOS device. Cons: Can only test via TestFlight after upload (someone with iPhone needs to install via TestFlight).

→ Follow Path B at step 5.

1Apple Team Setup

1.1 Accept the team invitation

  1. Check email for invitations from Apple Developer Program and App Store Connect
  2. Accept both with the Apple ID you'll use for development
  3. If client hasn't sent invites: ask them to log into appstoreconnect.apple.com → Users and Access → add you with role Admin or App Manager

1.2 Verify Program License Agreement is accepted

Log into developer.apple.com/account. If you see a yellow banner about an "updated PLA", the account holder (not you) must accept it. Ask the client.

1.3 Add Apple ID to Xcode

  1. Open Xcode → menu Xcode → Settings (⌘,)
  2. Click Accounts tab
  3. Click + bottom-left → Apple ID → sign in
  4. Confirm the client's team (e.g., MAICAFE LTD) appears under "Teams"

2Register App ID

Go to developer.apple.com → Certificates, Identifiers & Profiles → Identifiers

  1. Top-right team selector → confirm correct team
  2. Click the + next to "Identifiers"
  3. Select App IDs → Continue
  4. Select App → Continue
  5. Fill in:
    • Description: Your app name (no special characters — no &, no apostrophes)
    • Bundle ID: Click Explicit → enter exactly as in Xcode (e.g., com.maicafe.mcCafeApp)
  6. Scroll to Capabilities — tick:
    • ✅ Push Notifications (if you use push)
    • ✅ Sign in with Apple (only if you use it)
    • ✅ Associated Domains (only if you use universal links)
  7. Click Continue → review → Register

3Create APNs Auth Key

Only needed if your app uses push notifications. One key works for all apps in the team.

  1. Go to developer.apple.com → Keys
  2. Click + next to "Keys"
  3. Key Name: e.g., MaiCafe APNs Key (no special chars)
  4. Tick Apple Push Notifications service (APNs)
  5. Click Configure next to APNs:
    • Environment: Sandbox & Production (one key for both dev/TestFlight and App Store)
    • Key Type: Team Scoped (All Topics) — simpler
  6. Save the config → click Continue → Register
  7. Click Download — a .p8 file downloads
  8. 📋 Note down the Key ID (10 chars) — visible at top of page
⚠️ One-Time Download The .p8 file can ONLY be downloaded once. Store it securely. If lost, revoke and create a new key.

4Firebase Setup (for Push)

Only needed if you use Firebase Cloud Messaging.

4.1 Confirm iOS app exists in Firebase

  1. Open Firebase Console → your project
  2. Project Settings (gear icon) → General tab → scroll to "Your apps"
  3. Confirm an iOS app exists with the bundle ID matching Xcode
  4. If missing: click Add app → iOS → enter bundle ID → download GoogleService-Info.plist → place in ios/Runner/

4.2 Upload APNs key to Firebase

  1. Project Settings → Cloud Messaging tab
  2. Scroll to Apple app configuration
  3. Click Upload under "APNs Authentication Key"
  4. Fill in:
    • APNs auth key file: select the .p8
    • Key ID: the 10-character ID from step 3.7
    • Team ID: your Apple Team ID
  5. Click Upload
  6. Repeat for Production slot if you see two slots (Development + Production). Same file, same key ID, same team ID.

5Xcode Configuration

5.1 Open the project correctly

cd ~/path/to/your/flutter_project
open ios/Runner.xcworkspace
⚠️ Workspace, Not Project Always open Runner.xcworkspace (white icon), NOT Runner.xcodeproj (blue icon). The workspace includes CocoaPods dependencies.

5.2 Find the Runner target

  1. Left sidebar → click the blue Runner icon at the top (project, not folder)
  2. Center pane → left column shows PROJECT and TARGETS
  3. Under TARGETS → click Runner (not RunnerTests)
  4. Top tabs → Signing & Capabilities

5.3 Set Team

  1. Click Team dropdown → select your client's team
  2. If team doesn't appear: go to Xcode → Settings → Accounts and verify Apple ID is signed in with the right account

5.4 Add Capabilities

Click + Capability button (top of Signing & Capabilities tab) and add:

  • Push Notifications (if using push)
  • Background Modes → tick Remote notifications (if using push)
  • Sign in with Apple (if used)

5.5 Add Info.plist entries

Edit ios/Runner/Info.plist and ensure these are present:

<key>UIBackgroundModes</key>
<array>
  <string>remote-notification</string>
</array>
<key>ITSAppUsesNonExemptEncryption</key>
<false/>

Plus any usage descriptions for permissions you actually use (only add what's needed — Apple rejects fake declarations):

<key>NSCameraUsageDescription</key>
<string>Why your app needs the camera</string>

<key>NSPhotoLibraryUsageDescription</key>
<string>Why your app needs photos</string>

<key>NSLocationWhenInUseUsageDescription</key>
<string>Why your app needs location</string>

PATH A With iPhone — Automatic Signing

  1. Tick Automatically manage signing in Signing & Capabilities
  2. Connect your iPhone via USB. Trust the computer on the device.
  3. Top toolbar → device dropdown → select your iPhone
  4. Xcode auto-registers the device to the team. The "Communication with Apple failed" warning clears.
  5. Status section should show:
    • Provisioning Profile: Xcode Managed Profile
    • Signing Certificate: Apple Development
    • No yellow warnings
  6. Press ⌘R to build & run on your iPhone for testing

Continue to Step 6: Pre-Build Checks.

PATH B No iPhone — Manual Signing

This path skips automatic signing because it requires a registered device.

5B.1 Create iOS Distribution Certificate

  1. Xcode → menu Xcode → Settings (⌘,)
  2. Accounts tab → select your Apple ID
  3. Right side → Teams section → select your team → click Manage Certificates…
  4. Bottom-left → + → Apple Distribution
  5. Wait ~5s — new "Apple Distribution" certificate appears
  6. Click Done

5B.2 Create App Store Provisioning Profile (manual)

  1. Go to developer.apple.com → Profiles
  2. Click + → under Distribution → select App Store Connect → Continue
  3. App ID: select your app (e.g., MaiCafe) → Continue
  4. Certificates: tick the Apple Distribution cert you just created → Continue
  5. Profile Name: e.g., MaiCafe App Store → Generate
  6. Download the .mobileprovision file
  7. Double-click the downloaded file to install it (no UI confirmation appears — that's normal)

5B.3 Configure Xcode for manual signing

  1. Back in Xcode → Runner target → Signing & Capabilities
  2. Untick "Automatically manage signing" → confirm "Disable Automatic"
  3. At the top of the tab → click Release filter button
  4. In the Signing section:
    • Team: your client's team
    • Provisioning Profile: dropdown → select MaiCafe App Store (the one you created)
    • Signing Certificate: auto-populates as Apple Distribution
  5. Click Debug filter button → set the same profile and team (works for both)
  6. Status should now show no errors
ℹ️ Yellow Warnings Are OK You may see "Communication with Apple failed" warnings — they're harmless for App Store builds because the archive uses your manual Distribution profile.

6Pre-Build Checks

6.1 Version bump (if this isn't the first upload)

Edit pubspec.yaml. The format is marketing_version+build_number. Apple requires the build number to increase each upload:

# First submission
version: 1.0.0+1

# Resubmitting after fix
version: 1.0.0+2

# Next marketing version
version: 1.0.1+1

6.2 Decide iPad support

Check ios/Runner.xcodeproj/project.pbxproj:

grep TARGETED_DEVICE_FAMILY ios/Runner.xcodeproj/project.pbxproj
  • "1" = iPhone only
  • "1,2" = iPhone + iPad (requires iPad screenshots too)
  • "2" = iPad only

If your app isn't designed for iPad, set it to "1". Otherwise you'll be forced to provide iPad screenshots and Apple may reject if iPad layout is broken.

6.3 Run pre-build commands

cd ~/path/to/flutter_project
flutter clean
flutter pub get
cd ios && pod install && cd ..
flutter build ios --release --no-codesign

--no-codesign lets Flutter compile without signing — Xcode signs during Archive.

7Archive in Xcode

  1. In Xcode top toolbar → device dropdown → select "Any iOS Device (arm64)" (under "Build" section, NOT "Any iOS Simulator")
  2. Mac menu bar → Product → Archive
  3. Wait 5–10 min — progress bar shows "Archiving Runner..."
  4. When done, the Organizer window opens automatically
⚠️ Xcode Cloud Popup Xcode may prompt to set up Xcode Cloud — click "Don't Ask Again" or "Remind Me Later". Not needed for manual submissions.

8Upload to App Store Connect

In the Organizer window:

  1. Select your latest archive (top of list)
  2. Top-right → Distribute App
  3. Path A only If using automatic signing, select App Store Connect → Distribute → walk through with defaults
  4. Path B If using manual signing, select Custom → Distribute (this gives access to manual signing controls)

Wizard screens (Custom path)

  1. Select a method: App Store Connect → Next
  2. Distribution options: keep defaults checked (Upload symbols, Manage version) → Next
  3. Select certificate and profiles:
    • Distribution certificate: Default (Apple Distribution)
    • Runner.app → dropdown → select your manual profile (e.g., MaiCafe App Store)
  4. Review: verify Version, Profile, Certificate → click Upload
  5. Wait 2–5 min for upload

Keychain prompt during upload

You'll see a dialog: "codesign wants to access key Apple Distribution in your keychain".

  • Type your Mac login password
  • Click "Always Allow" (NOT "Allow", which prompts repeatedly; NOT "Deny", which fails the upload)

Apple processing

After "Upload Successful", Apple processes the build for 15–45 minutes. You'll get an email when it completes.

9Create App in App Store Connect

Skip this step if the app record already exists.

  1. Go to App Store Connect → Apps
  2. Top-right team selector → confirm correct team
  3. Click + → New App
  4. Fill in:
    • Platforms: ✅ iOS
    • Name: Your app name as it will appear on App Store
    • Primary Language: English (U.K.) or your locale
    • Bundle ID: dropdown — select the one you registered in step 2
    • SKU: internal unique ID (e.g., MAICAFE001)
    • User Access: Full Access
  5. Click Create

10.2 Recommended screenshot order (first 3 show in search)

  1. Home / main screen — strongest first impression
  2. Product/detail page — shows ordering flow
  3. Cart / checkout — conversion point
  4. Order tracking / confirmation
  5. Login/Welcome (optional)

10.3 Upload via Media Manager

  1. App Store Connect → your app → iOS App 1.0 version page
  2. Click View All Sizes in Media Manager (top-right of screenshots section)
  3. Drag screenshots into the iPhone 6.9" Display section
  4. If a 6.5" section auto-derives and shows a dimension warning, click Edit → Delete All for that section (6.5" is optional)
  5. Return to version page

11Metadata & URLs

On the iOS App 1.0 version page, fill in:

FieldLimitNotes
Promotional Text 170 chars Optional. Appears above description. Can be updated without re-review.
Description 4,000 chars Required. Marketing copy. Match app behavior — Apple checks for contradictions.
Keywords 100 chars Comma-separated. Don't repeat words from app name (already indexed). E.g., coffee,cafe,order,pickup,food,drinks,uk,takeaway
Support URL — Required. Must be HTTPS. Page must exist (no 404). Can use https://site.com/#contact anchor.
Marketing URL — Optional. App's homepage or landing page.

Click Save at the top-right after filling.

11.1 Attach build

  1. Scroll to Build section
  2. Click + Add Build (only shows after Apple processed your upload — ~30 min)
  3. Select your version (e.g., 1.0.0 (1)) → Done

12App Privacy Declarations

Left sidebar → App Privacy

12.1 Privacy Policy URL

Required. Add the URL to your live privacy policy page.

12.2 Data Types — what to tick

Tick only what your app actually collects. For a typical café/ordering app:

Physical Address✅ If app stores addresses
IdentifiersUser ID✅ Yes (account ID)
Device ID✅ Yes (FCM token)
PurchasesPurchase History✅ Yes (order history)

⚠️ "Email Address" vs "Emails or Text Messages" These names confuse people. Email Address (Contact Info) = the user's email for login. Emails or Text Messages (User Content) = the BODY of emails/SMS your app reads. Most apps only need the first.

12.3 For each ticked data type, answer 3 questions

For most apps the answers are identical for every data type:

QuestionAnswer
How is this data used?✅ App Functionality only
Linked to user's identity?✅ Yes
Used to track user?❌ No (unless sharing with ad networks)
⚠️ Tracking Saying YES to tracking shows an alarming "Data Used to Track You" badge on your App Store listing. Only say YES if you genuinely share data with third-party advertisers or data brokers.

12.4 Publish

Click Publish (top-right) when all data types are set up and show green checkmarks.

13Age Rating

Left sidebar → App Information → scroll to Age Ratings → click Edit

For most non-game business apps, answer None or No to every question across all 7 steps. Result: 4+ rating.

Final step asks about:

  • Age Categories and Override: Not Applicable
  • Made for Kids: No (unless app is specifically for kids)

Recommended: Manually release this version. After Apple approves, you click a "Release This Version" button when you/the client are ready. Avoids surprise launches at unexpected times.

16Submit for Review

  1. Top-right of version page → click Add for Review
  2. If button is greyed out, hover the icon next to each section — it'll show what's missing
  3. A "Draft Submission" panel slides in from the right
  4. Click Submit for Review
  5. Answer any final questions:
    • Export Compliance (encryption)? No (since you set ITSAppUsesNonExemptEncryption = false)
    • Third-party content? No
    • Advertising Identifier (IDFA)? No (unless you actually use it)

Status changes to "Waiting for Review". 🎉

Troubleshooting

"Communication with Apple failed: no devices"

Cause: Automatic signing wants a development profile, which requires a registered iOS device.

Fix: Switch to Path B: Manual Signing. The warning is harmless for App Store builds anyway.

"No profiles for 'com.x.y' were found"

Cause: The bundle ID isn't registered in the developer portal under the current team.

Fix: Register the App ID (Step 2). Make sure you're in the correct team.

"Cloud signing permission error" during upload

Cause: Wizard tried to use Xcode-managed automatic signing but you don't have permission for cloud certs.

Fix: Distribute via Custom path (not "App Store Connect" default) → select Manually manage signing → pick your manual Distribution profile.

"You must upload a screenshot for 13-inch iPad displays"

Cause: Your build was compiled with TARGETED_DEVICE_FAMILY = "1,2" (supports iPad).

Fix: Change to "1" in project.pbxproj, bump build number in pubspec.yaml, rebuild & re-upload.

Keychain dialog keeps appearing

Cause: You clicked "Allow" instead of "Always Allow".

Fix: Each time, click "Always Allow". After the first one, it should stop asking.

Build doesn't appear in App Store Connect after upload

Cause: Apple is still processing (15–45 min, sometimes 2h during peak).

Fix: Wait for the "Your build is ready" email. If it's been > 2h and no email, check email spam folder, or contact App Store Connect support.

"Missing Push Notification Entitlement" email warning

Cause: False positive from Apple's automated scan when you have FCM but don't actually use background pushes.

Fix: Ignore the email — the actual entitlement is present in your build (you added Push Notifications capability). This warning doesn't block submission.

App Review rejected — "Demo account doesn't work"

Cause: Account requires email OTP at login that reviewer can't access.

Fix: Pre-verify the account in your production system. Or create a backdoor "magic OTP" that always works for that specific email. Add details to review notes.

Post-Submission

Status timeline

  • Waiting for Review — submitted, in queue (typically < 24h)
  • In Review — reviewer is actively checking (typically a few hours)
  • Pending Developer Release — approved! Click "Release This Version" when ready
  • Rejected — Apple opened Resolution Center with feedback
  • Ready for Sale — live on App Store

If rejected

  1. Go to App Store Connect → app → Resolution Center on left sidebar
  2. Read Apple's specific reason
  3. Fix the issue (could be metadata, code, or just an explanation)
  4. For metadata-only fixes: edit text/screenshots → resubmit (no new build needed)
  5. For binary fixes: bump build number, rebuild, upload, attach new build, resubmit
  6. You can also reply in Resolution Center if you disagree or need clarification — reviewers usually respond within 24h

Releasing Updates

For minor changes (no code change — text/screenshots/etc.)

  1. App Store Connect → your app → click + Version or Platform on left sidebar → iOS
  2. Enter new version (e.g., 1.0.1)
  3. Update text/screenshots as needed
  4. No need to re-attach a build if you're not changing code (but most updates do change code)
  5. Submit for Review

For code updates

  1. Bump version in pubspec.yaml (e.g., 1.0.0+1 → 1.0.1+1)
  2. Make your code changes
  3. Repeat steps 6–8 (build, archive, upload)
  4. Create new version in App Store Connect
  5. Attach new build
  6. Update "What's New in This Version" text
  7. Submit for Review
💡 Phased Release For updates, consider enabling Phased Release for Automatic Updates in the version page. It rolls out over 7 days to ~1%, 2%, 5%, 10%, 20%, 50%, 100% — minimizing impact if there's a bug.

Final Pre-Submission Checklist

Before clicking "Submit for Review", verify:

  • Build attached — version shows in Build section, no "Add Build" placeholder
  • Screenshots — at least 3 for 6.9" iPhone, all show real app screens
  • Description — matches actual app behavior (no "delivery" if pickup-only)
  • Demo credentials work — you've tested login yourself
  • Privacy Policy URL — loads successfully (test in incognito browser)
  • Support URL — loads successfully
  • App Privacy — all data types declared, no false declarations
  • Age Rating — questionnaire complete
  • Category — set to most appropriate
  • Pricing — Free (or correct price), at least one country selected
  • Review notes — detailed enough that a non-domain-expert reviewer can navigate the app
  • Release setting — Manually release (recommended for v1.0)
  • Copyright — current year and correct entity name
  • Subtitle — concise value prop (optional but helps conversion)
