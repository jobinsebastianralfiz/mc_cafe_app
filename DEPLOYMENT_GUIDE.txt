STEP 1: CONFIGURE iOS PROJECT
-----------------------------
1. Open terminal and navigate to project:

--------------------------
Edit pubspec.yaml:

Format: VERSION+BUILD_NUMBER
- 1.0.0 = Version displayed to users (major.minor.patch)
- +1 = Build number (increment for EACH upload to App Store Connect)

Example progression:
- First release: 1.0.0+1
- Bug fix: 1.0.1+2
- New feature: 1.1.0+3
- Major update: 2.0.0+4

4. ANDROID DEPLOYMENT (PLAY STORE)
================================================================================

STEP 1: CREATE KEYSTORE (first time only)
-----------------------------------------
Run in terminal:

keytool -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA \
  -keysize 2048 -validity 10000 -alias upload

You'll be prompted for:
- Keystore password: (choose strong password, SAVE IT!)
- Your name, organization, city, state, country
- Key password: (can be same as keystore password)

IMPORTANT: Save keystore file and passwords securely!
           You CANNOT upload updates without the same keystore!

STEP 2: CONFIGURE SIGNING
-------------------------
1. Create file: android/key.properties
   (Add to .gitignore to keep secure!)

   Content:
   storePassword=YOUR_KEYSTORE_PASSWORD
   keyPassword=YOUR_KEY_PASSWORD
   keyAlias=upload
   storeFile=/Users/jobinsebastian/upload-keystore.jks

2. Edit android/app/build.gradle.kts:

   Add before android { block:

   def keystoreProperties = new Properties()
   def keystorePropertiesFile = rootProject.file('key.properties')
   if (keystorePropertiesFile.exists()) {
       keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
   }

   Inside android { block, add:

   signingConfigs {
       release {
           keyAlias keystoreProperties['keyAlias']
           keyPassword keystoreProperties['keyPassword']
           storeFile keystoreProperties['storeFile'] ? file(keystoreProperties['storeFile']) : null
           storePassword keystoreProperties['storePassword']
       }
   }

   Update buildTypes:

   buildTypes {
       release {
           signingConfig signingConfigs.release
       }
   }

STEP 3: BUILD APP BUNDLE

Run in terminal:

5. COMMON ISSUES & SOLUTIONS
================================================================================

iOS ISSUES:
-----------

Issue: "No signing certificate"
Solution:
   In Xcode: Preferences → Accounts → Select team → Download Manual Profiles

Issue: "Provisioning profile doesn't include capability"
Solution:
   1. Go to developer.apple.com → Certificates, IDs & Profiles
   2. Find your App ID
   3. Enable required capabilities
   4. Regenerate provisioning profile

Issue: Build fails with CocoaPods error
Solution:
   cd ios
   pod deintegrate
   rm Podfile.lock
   pod install --repo-update
   cd ..
   flutter clean
   flutter build ios --release

Issue: "The bundle identifier cannot be changed"
Solution:
   Must create new app in App Store Connect with new bundle ID

Issue: Archive fails with bitcode error
Solution:
   In Xcode: Build Settings → Enable Bitcode → No

Issue: "Missing compliance" in TestFlight
Solution:
   Must answer export compliance question for each build

ANDROID ISSUES:
---------------

Issue: "Keystore was tampered with or password incorrect"
Solution:
   Double-check password in key.properties matches keystore

Issue: "App bundle larger than 150MB"
Solution:
   - Use flutter build appbundle --target-platform android-arm64
   - Enable ProGuard/R8 minification
   - Remove unused assets

Issue: "Version code already exists"
Solution:
   Increment versionCode in pubspec.yaml (the +N part)

Issue: "Target SDK must be 34 or higher"
Solution:
   In android/app/build.gradle.kts, ensure:
   targetSdk = 34 (or flutter.targetSdkVersion if it's 34+)

Issue: App rejected for policy violation
Solution:
   - Read rejection email carefully
   - Common issues: privacy policy, permissions, content
   - Fix and resubmit
